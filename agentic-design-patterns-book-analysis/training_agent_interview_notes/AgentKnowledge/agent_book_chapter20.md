# Prioritization (优先级排序) - Agent 设计模式

## 1. 核心理念与架构定位
### 解决的核心痛点
- **资源诅咒**：面对大模型的并发限制 (Rate Limits)、上下文窗口上限以及高昂的 Token 成本，系统不可能同时且同等地处理所有请求。
- **任务冲突**：当子 Agent 产生相互依赖或抢占共享工具（如数据库写入锁）时，需要建立明确的仲裁机制。
### 本质定义
- 它是 Agent 系统的“中央调度器 (Scheduler)”，促使系统从“顺序盲目执行”向**价值驱动执行 (Value-Driven Execution)** 进行范式转移。

## 2. 优先级评估与调度算法
### 静态规则与启发式排序 (Rule-based)
- **机制**：依赖预设的硬性业务逻辑（如 FIFO 先进先出，或基于特定元数据标签 `[Critical]` 的优先队列）。
- **特性**：执行开销极低，适合高度结构化的任务流。
### LLM 动态认知评分 (LLM-based Scoring)
- **机制**：利用大模型的语义理解能力，针对任务的上下文进行“重要度”和“紧急度”的打分（通常借用艾森豪威尔矩阵原理）。
- **特性**：更具灵活性，能够根据目标的变化（Goal Setting）动态改变同一任务的权重。
### 动态重排与中断 (Dynamic Reprioritization)
- **机制**：优先级并非一成不变。当环境发生突变（如关键 API 宕机，或接收到人类在环 HITL 的紧急干预）时，Agent 必须能够实时挂起当前的低优计算，将异常处理提升为最高优先级。

## 3. 框架落地与底层编排
### 状态树与优先队列 (Priority Queues)
- 在 LangGraph 等状态机架构中，通常需要引入一个全局的 `Task_Pool` 状态变量和一个专门的 `Priority_Router_Node`。该节点每次只从池中 `pop` 出当前分值最高的任务进入下一环节。
### 与“资源感知 (Resource-Aware)”的深度协同
- **算力倾斜**：高优先级任务分配给最强的大模型（如 Gemini Pro）和最多的重试次数；低优先级任务直接降级分配给轻量模型或直接放入闲时批处理队列。
