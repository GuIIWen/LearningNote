# Multi-Agent Collaboration (多智能体协作) - 智能 Agent 设计模式

## 1. 核心哲学：从单体到协同
### 解决 Monolithic 局限性
- **专注性 (Focus)**：单个 Agent 难以同时精通多个垂直领域。通过拆分，每个 Agent 只负责一个原子领域。
- **鲁棒性 (Robustness)**：局部失败不会导致整个系统崩溃。
- **可扩展性 (Scalability)**：可以根据业务需求，灵活增加或替换特定功能的 Agent。
### 协作本质
- **社会化推理**：模拟人类组织结构，通过对话、竞争或共识解决问题。

## 2. 两种主流协作架构模式
### 模式 A：中心化编排 (Orchestration / Manager-Worker)
- **机制**：存在一个“经理 Agent (Manager)”，负责任务分配、进度监控和最终结果整合。
- **特点**：控制力强，逻辑清晰，适用于流程相对确定的业务。
### 模式 B：去中心化编排 (Choreography / Peer-to-Peer)
- **机制**：Agent 之间地位平等，通过发布/订阅消息或直接对话触发协作，没有绝对的控制中心。
- **特点**：灵活性极高，适用于探索性、非线性的复杂任务（如：AutoGen 的典型场景）。

## 3. 协作的关键基础设施
### 角色定义 (Role Definitions)
- **Persona 设定**：为每个 Agent 注入特定的“专家权重”。例如：航空本体建模专家、数据清洗算法员、逻辑校验员。
### 通信协议 (Communication Protocols)
- **标准化接口**：如何定义 Request 和 Response 的 JSON 结构。
- **MCP 协议集成**：实现跨系统的工具与上下文共享。
### 状态共享与记忆管理 (Shared State & Memory)
- **黑板模式 (Blackboard Pattern)**：所有 Agent 共享一个全局状态池，读写进度。
- **短期/长期记忆**：确保协作过程中的上下文不会在多次对话中丢失。

## 4. 工业级应用场景 (以航空制造本体建模为例)
### 多角色联合建模流水线
- **Agent A (解析员)**：利用视觉或长文本能力处理 Boeing 零件图纸。
- **Agent B (建模员)**：基于解析结果，在标准本体库中寻找对应关系。
- **Agent C (算法员)**：运行确定性的**算法**，校验图谱的环路冲突。
- **Agent D (对齐员)**：使用 GRPO 等技术生成的对齐策略，确保输出符合行业安全标准。
### 复杂故障诊断与排程
- 多个 Agent 同步评估供应链、生产线状态及技术风险，通过“辩论”产出最优排程方案。

## 5. 主流框架落地
### LangGraph
- 侧重于**图结构 (Graph-based)** 的确定性流转，擅长处理带有循环和复杂条件的中心化协作。
### CrewAI
- 强调**角色驱动 (Role-driven)**，通过 `Process` 定义任务流，简单直观。
### AutoGen
- 擅长**多 Agent 对话 (Conversation-based)**，动态性极强，适合需要多轮讨论才能定论的场景。
