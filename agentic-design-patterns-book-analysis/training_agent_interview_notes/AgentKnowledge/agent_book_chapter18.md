# Guardrails & Safety Patterns (护栏与安全模式)

## 1. 核心理念与架构定位
### 防御纵深 (Defense in Depth)
- 永远不要绝对信任基础模型（即使它经过了完美的对齐训练）。
- 在 Agent 与外部环境交互的每个边界处部署独立的校验机制。
### 职责分离
- 大模型负责“开放式推理与生成”。
- 护栏负责“确定性的拦截与阻断”，两者在架构上解耦。

## 2. 护栏的三大拦截层
### 层级 1：输入护栏 (Input Guardrails)
- **作用位置**：用户 Prompt 到达 LLM 之前。
- **核心防御**：
  - 拦截越狱 (Jailbreaks) 与提示词注入攻击。
  - PII 脱敏（将机密的波音供应商数据在传入大模型前进行掩码处理）。
### 层级 2：输出护栏 (Output Guardrails)
- **作用位置**：LLM 生成结果之后，交由外部系统之前。
- **核心防御**：
  - **结构校验**：强制 JSON Schema 验证，缺字段直接打回（触发自反思）。
  - **事实幻觉拦截**：使用轻量级判别模型或知识抽取算法，校验输出中是否捏造了不存在的航空本体节点。
### 层级 3：执行护栏 (Execution Guardrails)
- **作用位置**：工具调用 (Tool Use) 与 MCP Server 内部。
- **核心防御**：
  - **权限沙箱 (Sandboxing)**：Agent 运行在隔离的容器中，防止恶意代码执行。
  - **最小权限原则 (Least Privilege)**：Agent 默认只具有只读权限，涉及图数据库写入的操作必须触发审批流 (HITL)。

## 3. 护栏的底层实现机制
### 确定性算法 (Rule-based)
- 极低延迟，100% 可控。例如利用正则表达式拦截特定的禁用词汇，或利用 JSON 解析器校验结构。
### 语义与模型驱动 (Model-based)
- 部署极小参数的专用分类模型（如 LlamaGuard 或基于你们内部数据微调的微型分类器），在向量空间中判断输入/输出是否跨越了安全边界。

## 4. 工业级应用映射 (航空制造本体构建)
### 知识图谱的边界约束
- Agent 在进行复杂本体推理时，输出护栏中必须硬编码航空工业规范（如 STEP AP242 协议）。如果 Agent 推理出“机翼包覆在发动机内部”这种违背物理拓扑的结论，护栏算法直接将其判定为致命级幻觉并阻断。
### MCP 层的灾难隔离
- 当通过 A2A 协议委派下游 Agent 修改数据库时，接收端 Agent 的护栏必须验证请求来源签名，并在执行 `UPDATE` 指令前进行强制备份机制。
