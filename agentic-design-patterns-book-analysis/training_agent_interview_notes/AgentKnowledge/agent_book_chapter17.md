# Reasoning Techniques (推理技术) - 智能 Agent 设计模式

## 1. 核心理念与范式转移
### 从 System 1 到 System 2
- **System 1 (快思考)**：传统的 LLM 直觉式生成，速度快，但遇到复杂逻辑容易产生幻觉。
- **System 2 (慢思考)**：引入深思熟虑的推理算法，让模型在输出最终答案前，经历规划、拆解、评估和纠错的内部过程。
### 白盒化思维 (Explicit Internal Thinking)
- 强制模型将隐式的推理过程通过文本结构化地暴露出来，提高可观测性、可解释性和调试效率。

## 2. 基础与探索性推理模式
### Chain-of-Thought (CoT / 思维链)
- **机制**：通过“一步步思考”的引导，将复杂的大问题拆解为线性的、易于管理的原子步骤。
- **局限**：单线推进，一旦某个中间环节推理错误，后续结论将全盘崩溃（误差累积）。
### Tree-of-Thought (ToT / 思维树)
- **机制**：在 CoT 基础上引入非线性分支。将推理过程视作在树状空间中的搜索（如 BFS 或 DFS）。
- **流程**：生成多个可能的分支思路 -> 独立评估（打分）每个分支的潜力 -> 剪枝掉无效路径 -> 继续向下探索。
- **优势**：具备前瞻性和回溯能力，极大提升了解决高度复杂结构问题的准确率。

## 3. 交互与符号计算推理
### ReAct (Reasoning + Acting)
- **机制**：将“内部思考 (Thought)”与“外部执行 (Action)”交织的循环模式。
- **流程**：Agent 思考当前该做什么 -> 调用特定工具采取行动 -> 观察 (Observation) 工具返回的结果 -> 进入下一轮思考。是现代 Agent 框架最核心的流转骨架。
### Program-Aided Language Models (PALMs)
- **机制**：大模型负责理解语义和拆解逻辑，但将具体的数学计算、确定性逻辑推导卸载 (Offload) 给外部 Python 解释器或符号求解器。
- **优势**：完美弥补了 LLM 计算能力差的短板。

## 4. 评估与对抗性推理
### Self-Correction (自我纠正)
- 引入内源性反馈闭环，模型审视自己刚刚生成的输出，寻找逻辑漏洞并迭代修正。
### Chain/Graph of Debates (辩论链/辩论图)
- **机制**：实例化多个不同视角或参数的模型进行“同行评审 (Peer Review)”。
- **流程**：模型 A 提出方案，模型 B 寻找逻辑冲突并反驳，模型 C 进行总结。通过对抗性的辩论网络，收敛出最可靠的结论。

## 5. 核心技术研究与落地场景
### 复杂跨领域本体建模
- 在进行航空制造本体建模的**核心技术研究**中，单纯的 CoT 无法处理庞大的实体关系网。采用 **ToT (思维树)**，Agent 能够在一系列可能的波音组件层级树中进行搜索，并利用内置评估机制剔除违背物理常识的装配关系分支。
### 严密逻辑的自动化排查
- 当分析波音技术规范并进行数据抽取时，结合 **PALMs 模式**，Agent 可将提取到的结构约束自动转化为 Python 代码并执行校验，确保逻辑绝对严密。
