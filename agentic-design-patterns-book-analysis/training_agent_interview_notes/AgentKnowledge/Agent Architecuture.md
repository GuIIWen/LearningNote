##### 状态评估Agent
![[mermaid-diagram (1).png|697]]

1. 该架构描述了一个**状态评估 Agent 的闭环决策系统**：系统首先从 Workflow、实时指标、系统信号和日志中获取多源数据，经由状态聚合器进行时间窗口处理和特征提取，并构建包含历史趋势的上下文；随后进入评估层，通过规则引擎与异常检测模型对当前状态进行多维分析，并在评估融合器中形成统一判断；决策引擎基于评估结果进行分级决策（如继续、降级、重试、告警或终止），并由动作调度器执行具体响应；所有执行结果与状态变化被记录回状态仓库，用于后续策略优化与模型更新，从而形成一个具备**自适应能力的持续评估与自反馈闭环系统**。

2. 时间窗口处理是指在评估系统状态时，不只依赖某一时刻的瞬时数据，而是基于最近一段时间内的连续数据进行统计与分析（如均值、波动、变化率），从而降低噪声干扰并提升判断稳定性；而构建历史趋势上下文，则是在此基础上进一步理解数据随时间的变化轨迹（如持续上升、突变或周期波动），使系统不仅“看到当前”，还能“理解变化过程”。两者结合，使状态评估 Agent 从简单的阈值判断升级为具备趋势感知和上下文理解能力的决策系统，从而显著减少误报、支持提前预警，并提升整体评估的准确性与鲁棒性。

##### 记忆服务Agent

![[mermaid-diagram (3).png]]
用户输入
   ↓
Memory Controller
   ↓
生成 Retrieval Request（带意图/范围/约束）
   ↓
检索策略模块
   ↓
选择数据源 + 规划检索流程 + 设置参数
   ↓
执行检索（Vector / Graph / KV）
   ↓
返回候选记忆

1. Memory Controller 会生成一个结构化的检索请求（包含查询语义、检索意图、范围和约束），检索策略模块根据该请求动态选择数据源（如向量库、图数据库或用户画像）、确定检索流程（如召回与重排序）以及调整参数（如Top-K和权重），从而执行最合适的检索路径。
2. 这个记忆 Agent 架构是一个以 **Memory Controller 为核心的分层记忆与动态演化系统**：当用户输入到来时，记忆决策器首先基于当前对话上下文生成结构化的检索请求，并交由检索策略模块决定从哪些记忆源（短期会话、语义记忆、结构化记忆、用户画像）中检索以及采用何种检索方式；检索结果与会话上下文一起由上下文构建器进行融合，形成统一输入供模型推理使用。完成响应后，系统进入写入与维护阶段：写入策略对新信息进行筛选、去重和压缩，决定是否写入以及写入到哪一类记忆中；随后记忆更新模块对已有记忆进行全局维护，包括对语义记忆的去重与合并、对结构化记忆的冲突覆盖与关系更新，以及对用户画像的偏好调整与权重演化。整个系统由此形成“按需检索—融合推理—选择写入—持续更新”的闭环流程，使记忆不仅可被调用，还能长期保持一致性、有效性并随使用不断演进。

##### 假设生成器
###### 原架构图：

- ###### 架构核心模块流转分析

	- **输入与上下文锚定 (Open Problem -> Lit Reviewer):**
	    
	    - 系统以一个待解决的宏大目标（Goal）为起点。
	        
	    - `Lit Reviewer`（文献综述员）充当了上下文处理器（Context Provider）的角色。它不直接解决问题，而是负责检索、整理背景知识，建立知识基线。在多智能体系统中，这一步至关重要，它确保了后续生成的 Prompt 是基于坚实事实（Grounding）的，减少了下游模型的幻觉。
	        
	- **异构思维生成矩阵 (Expert A / B / C):**
	    
	    - 这是该系统最核心的生成环节。系统没有依赖单一的大模型进行穷举，而是实例化了三个带有不同系统提示词（System Prompts）和特定思维视角的Agent：
	        
	        - **Expert A (Divergent - 发散性):** 旨在打破常规，穷尽所有可能的边缘路径。
	            
	        - **Expert B (Lateral - 水平/侧向):** 强调跨界寻找灵感，可能跳出当前领域寻找解决方案。
	            
	        - **Expert C (Analogical - 类比):** 利用已知成熟领域的经验和模型，映射并推导当前未知问题的解。
	            
	    - **机制优势:** 这种设计有效规避了单一模型容易出现的“模式崩溃（Mode Collapse）”和同质化输出，保证了提案（Proposal）的多样性。
	        
	- **竞争性评估枢纽 (Debate Arena):**
	    
	    - 所有的 Proposal 汇聚于此。这里采用的是 **Elo Scoring（Elo评级系统）**。
	        
	    - 这与强化学习对齐（如 DPO、RLHF）中构建偏好数据集的底层逻辑高度一致。它通过特定的评分**算法**让不同提案进行两两对决或综合打分，评估其逻辑严密性与创新性。胜出者（WINNER）将被输出为最终的新颖假设（Novel Idea）。
	        

- ###### 进化机制：核心反馈闭环 (Mutate & Regen)

	图中红色的虚线回溯路径 `FLAWED (MUTATE & REGEN)` 是赋予系统“科研推理能力”的关键所在。
	
	- **回溯策略:** 当 `Debate Arena` 判定当前的 Proposal 都存在缺陷（FLAWED）无法胜出时，系统触发回溯。
	    
	- **切入点巧妙:** 注意，回溯的箭头指向的是 `Lit Reviewer`，而不是直接让三个 Expert 重新生成。这意味着系统认为：如果三个顶尖视角的专家都给不出好方案，问题大概率出在**上下文和视角构建**上。
	    
	- **变异 (Mutate):** 系统会要求 `Lit Reviewer` 调整综述方向，引入新的约束条件或变换分析粒度，从而改变分发给 Expert 的 Prompt。这是一种自顶向下的状态机重置，确保系统不会在错误的思路上陷入死循环。

![[mermaid-diagram (2) 1.png]]
1. 该假设生成Agent以开放问题为输入，首先通过文献与知识检索构建初始认知边界，在此基础上由多种专家模型（发散式、类比式、知识驱动）生成多样化候选假设，并统一转换为结构化表示（包含变量、因果关系与实验路径）；随后通过多目标评估器从新颖性、可行性、风险与逻辑一致性等维度对假设进行打分与筛选，进入仿真或实验沙盒进行验证；验证结果不仅用于筛选高质量假设，还驱动进化机制（变异与重组）生成新一轮候选，从而形成持续优化的搜索闭环；最终系统输出收敛后的Top-K高潜力假设，并将全过程经验沉淀至知识库以提升后续生成效率与质量。
