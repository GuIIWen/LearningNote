# Memory Management (记忆管理) - 智能 Agent 设计模式

## 1. 核心理念与分类
### 记忆的本质
- Agent 保留并利用过去交互、观察和学习经验中信息的能力。
- **目的**：做出明智决策、维护对话上下文、随时间持续改进策略。
### 短期记忆 (Short-term / Context Memory)
- **定义**：类似于人类的“工作记忆”，存在于 LLM 的当前上下文窗口中。
- **特点**：包含最近的对话、工具调用结果和反思；容量有限（受 Token 限制）；会话结束后即丢失（临时性）。
- **挑战**：即使存在“长上下文模型”，每次带入全量历史进行推理也极其昂贵且容易产生“迷失在中间 (Lost in the middle)”的问题。
### 长期记忆 (Long-term / Persistent Memory)
- **定义**：跨交互、跨任务的数据持久化存储库。
- **特点**：独立于 LLM 存在；通常依托于关系型数据库、图数据库或向量数据库 (Vector DB)。
- **机制**：通过语义搜索 (Semantic Search) 和检索增强生成 (RAG) 技术，在需要时提取信息并注入短期记忆。

## 2. 核心架构层级 (以 Google ADK 为例)
### Session (会话级线程)
- **功能**：跟踪单次交互线程，记录时间顺序的事件 (Events)。
- **生命周期**：由 `SessionService` 管理（启动、恢复、记录、销毁）。
### State (会话级状态/草稿本)
- **功能**：作为字典运作，存储当前交互中动态更新的变量（如任务进度、条件标志）。
