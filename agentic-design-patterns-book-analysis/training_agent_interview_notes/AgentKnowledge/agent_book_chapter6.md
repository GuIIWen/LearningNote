# Planning (规划) - 智能 Agent 设计模式

## 1. 核心理念与本质差异
### 核心定义
- **从“What”到“How”**：人类只提供高阶目标 (What) 与约束条件，由 Agent 自主探索并生成实现目标的执行路径 (How)。
### 动态性与适应性
- **非死板脚本**：计划只是起点，不是固定代码。Agent 能在执行过程中根据遇到障碍（如：数据库宕机、缺乏某种工具权限）重新评估状态并动态生成新计划。
### 权衡决策 (Trade-off)
- **发现路径 vs 预设流程**：
  - 如果业务流程高度确定（如：标准的财务报销流程），应使用固定工作流（限制 Agent 自主性以保证 100% 可靠）。
  - 如果业务涉及未知探索（如：复杂的航空本体建模故障排查），才应使用 Planning 模式。

## 2. 规划过程与运作机制
### 核心步骤
1. **状态理解**：解析当前初始状态（可用数据、工具、上下文）与目标状态。
2. **任务分解 (Decomposition)**：将宏大的目标拆解为离散的、可由具体工具或子 Agent 执行的子任务序列。
3. **依赖关系编排**：确立子任务执行的先后顺序（例如：必须先通过 MCP 查询到 Boeing 的图纸 ID，才能调用排程算法）。
4. **监控与重规划 (Re-planning)**：在执行过程中获取环境反馈，一旦出现偏差，立刻调整后续步骤。

## 3. 工业级应用场景
### 复杂信息综合与本体构建
- **场景**：输入海量混杂的航空制造技术规范，要求输出结构化的知识图谱。
- **Agent 规划链路**：规划收集数据 -> 规划消歧清洗 -> 规划实体抽取 -> 规划图谱映射。
### 动态过程与调度编排
- **场景**：航空生产线排程调度。
- **Agent 规划链路**：评估当前设备空闲状态 -> 规划工单优先级 -> 如果突发设备故障 -> 动态重新规划替代生产线。
### 机器人与自主系统空间导航
- **场景**：自主识别状态空间，在满足能耗和安全约束的前提下，规划出从起点到终点的最优行动序列。

## 4. 框架落地范式 (以 CrewAI / 架构层为例)
### 显式规划模式 (Explicit Planning)
- **机制**：在执行实质性动作前，强制大模型先输出一个明确的计划清单，供人类审核或系统记录。
- **案例应用**：在 Prompt 中明确要求输出分为 `### 计划` (List) 和 `### 执行结果` 两个独立部分。
### 隐式流转框架
- **LangGraph 视角**：相较于 CrewAI，在 LangGraph 中规划通常表现为图中的一个 `Planner Node`，该节点生成一个包含步骤的 List 存入状态机 (State)，然后由后续的执行节点逐个消耗这个 List，如果执行节点报错，则流转回 Planner 重新生成剩余计划。
