# Reflection (反思) - 智能 Agent 设计模式

## 1. 核心理念与机制
### 核心定义
- **元认知层 (Meta-cognition)**：Agent 评估自身工作、输出或内部状态的自我纠正机制。
- **反馈循环 (Feedback Loop)**：突破单向执行，引入迭代优化闭环。
### 运作流程
1. **执行 (Execution)**：生成初始输出或计划。
2. **评估/评审 (Evaluation/Review)**：针对事实、连贯性、指令遵循度等标准进行审查。
3. **反思/优化 (Reflection/Refinement)**：基于批评建议，调整参数或重新生成内容。
4. **迭代 (Iteration)**：重复上述步骤直至达到停止条件（如输出完美或达到最大循环次数）。

## 2. 关键架构设计：生成器-评审者模型 (Generator-Reviewer)
### 关注点分离 (Separation of Concerns)
- 避免“认知偏差”，让单一模型既当裁判又当运动员容易产生盲区。
### 角色定义
- **生产者 Agent (Generator)**
  - 职责：专注内容生成（如写代码、建模型、写方案）。
  - 动作：接收初始 Prompt 及后续的修改建议，产出内容。
- **评审者 Agent (Reviewer)**
  - 职责：扮演特定领域的专家（如“高级系统架构师”、“严格的事实核查员”）。
  - 动作：根据既定标准寻找漏洞、逻辑错误或幻觉，输出结构化的批评建议。

## 3. 增强反思效能的组件
### 对话记忆 (Memory)
- **作用**：让反思成为累积过程而非孤立事件。
- **机制**：通过维护交互历史，使 Agent 能够理解之前的错误并避免重复踩坑。
### 状态机与路由 (State & Routing)
- **作用**：在复杂框架（如 LangGraph / ADK）中，基于评审结果的 Status（如 "ACCURATE" 或 "INACCURATE"）动态路由至不同的下游节点。

## 4. 工业级应用场景 (以航空制造本体建模为例)
### 逻辑与实体一致性校验
- **生产者**：从 Boeing 规范中提取并构建初步的知识图谱节点。
- **评审者**：加载航空工业标准（如 STEP AP242 协议），评审生产者构建的层级关系是否违背物理常识或工业标准，提出修正建议。
### 复杂排程算法优化
- **生产者**：生成初步的生产排程 Python 算法。
- **评审者**：运行模拟测试，检查算法是否遗漏了关键边缘情况（如特定车间的设备维护停机时间），并打回重做。
### 多步推理求解
- 在遇到复杂的本体冲突时，评估中间推理步骤是否引入了逻辑矛盾。

## 5. 框架落地实现
### LangChain / LangGraph 实现
- **LCEL 组合**：通过外层 Python `for` 循环和状态列表，结合具体的 `reflector_prompt` 进行多次 LLM 调用。
- **停止条件设计**：设定特定的输出短语（如 `CODE_IS_PERFECT`）作为跳出循环的 Trigger。
### Google ADK 实现
- **SequentialAgent**：通过明确挂载 `LlmAgent` 的上下游关系，将状态键 (`draft_text`, `review_output`) 在图结构中流转。
