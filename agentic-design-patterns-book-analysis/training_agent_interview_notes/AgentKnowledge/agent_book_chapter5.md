# Tool Use (工具使用/函数调用) - 智能 Agent 设计模式

## 1. 核心本质与运作机制
### 本质定义
- **打破数据孤岛**：克服大语言模型（LLM）训练数据的静态限制。
- **能力边界拓展**：从单纯的“文本生成器”进化为具备“感知、推理和行动”能力的智能体。
### 标准运作流转 (6步闭环)
1. **工具定义**：向 LLM 注册外部函数（名称、目的、输入参数的严格结构，如 JSON Schema）。
2. **LLM 推理决策**：LLM 分析上下文，决定是否需要调用工具。
3. **参数生成**：LLM 提取所需参数，输出标准化的调用指令（如 JSON 对象）。
4. **框架拦截与执行**：Agent 编排层（如 LangChain）拦截指令，执行真实的外部代码/API。
5. **获取观察 (Observation)**：将外部系统返回的结果（数据、状态、报错等）抓取回来。
6. **LLM 处理响应**：将观察结果放入上下文窗口，由 LLM 进行下一步路由判断或输出最终答案。

## 2. 概念演进：从函数到“泛工具调用”
- **狭义 (Function Calling)**：调用预先写好的 Python 脚本或基础计算器。
- **广义 (Tool Use / MCP 视角)**：
  - 调用复杂的企业级 API 端点（如 Salesforce Graph API 查询）。
  - 调用高度专业化的数据清洗与知识图谱构建**算法**。
  - **A2A 交互**：将调用指令发送给系统内其他专业子 Agent（把 Agent 当作 Tool）。

## 3. 核心应用场景 (结合工业级业务)
### 外部数据获取与 API 交互
- **场景**：解决模型不知道“此时此刻此地”信息的痛点。
- **案例**：通过外部 ID (External ID) 查询 Salesforce 数据库，获取波音零部件的最新库存或供应商状态。
### 复杂计算与确定性逻辑
- **场景**：大模型算数极差且易出现幻觉。
- **案例**：在进行航空制造供应链排程时，Agent 提取出关键变量，将排程任务交由专属的运筹学**算法**工具去计算。
### 系统控制与操作执行 (Actuator)
- **场景**：在物理世界或数字系统中产生副作用（Side-effects）。
- **案例**：发送报警邮件、触发现场制造设备的检修工单。

## 4. 框架落地范式
### LangChain / LangGraph 生态
- `create_tool_calling_agent`：绑定 LLM、Prompt 与定义的 Tools。
- `AgentExecutor`：充当运行时引擎，处理 LLM 的动作输出，自动路由到具体工具并带回结果。
### CrewAI 生态
- 强调角色化（Role-playing）的 Agent。
- 在 `Agent` 定义时挂载 `@tool` 装饰器封装的 Python 函数。
- 强调健壮的错误处理（如引发明确的 `ValueError` 以触发 Agent 的反思与重试）。
### 协议层标准化 (MCP 集成)
- 通过 Model Context Protocol (MCP)，将零散的 API 统一封装为标准化 Server，实现跨 Agent 平台的即插即用。
